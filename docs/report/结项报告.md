## 一、项目概述 【中期必填】

> **1. 项目背景
> 校园内各类社团、学生组织（"公会"）在任务管理中普遍存在任务分配不透明、进度追踪困难、成员反馈不及时、缺乏统一的任务流转与状态管理平台等问题。本项目针对校园轻量化任务协作需求，开发校园公会任务流系统，实现学生组织内部任务发布、分配、执行、反馈的全流程数字化管理，提升协作效率，降低沟通成本。**

### **2. 系统目标 - 实现任务全生命周期管理，覆盖创建、分配、状态更新、进度追踪、提交、审核、驳回全流程。 - 为管理员提供成员管理、任务管理、数据统计、进度监控能力，提升组织管理效率。 - 为普通成员提供统一的任务接收、执行、提交、反馈入口，简化操作流程。 - 实现前端自动化构建与部署，保障系统可访问性与迭代效率。 - 系统稳定可用，满足校园社团日常任务管理需求。** 3. 开发环境

## 二、需求分析 【中期必填】

### 1. 功能需求

> 根据校园公会的任务管理场景，系统核心功能分为以下模块：

1.  \*\*\*\*用户与权限管理模块\*\*\*\*
    - 支持用户注册、登录，区分管理员（公会负责人）与普通成员角色。
    - 管理员可创建公会、添加成员、分配角色权限。
2.  \*\*\*\*任务管理模块\*\*\*\*
    - 管理员可创建任务、设置任务详情（描述、截止时间、负责人）。
    - 支持任务状态流转：待分配 → 已分配 → 执行中 → 已提交 → 已审核 /
      已驳回。
    - 成员可查看已分配任务、提交进度、上传结果、反馈问题。
3.  \*\*\*\*任务进度统计模块\*\*\*\*
    - 管理员可查看公会内所有任务的进度分布、成员完成率。
    - 支持按任务状态、时间范围筛选统计。
4.  \*\*\*\*前端交互模块\*\*\*\*
    - 提供任务列表、任务详情、个人中心等页面，支持响应式访问。
    - 前端页面通过 GitHub Pages 部署，实现静态资源的自动化构建与发布。

> \*\*\*\*核心业务流程\*\*\*\*：管理员创建任务 → 分配给指定成员 →
> 成员接收并执行任务 → 提交任务结果 → 管理员审核（通过 / 驳回）→
> 任务状态更新并同步至双方。

### 2. 非功能需求

- \*\*\*\*性能要求\*\*\*\*：系统支持至少 50
  名成员同时在线访问，页面响应时间≤2s；前端静态资源构建与部署流程耗时≤5
  分钟。
- \*\*\*\*安全要求\*\*\*\*：用户密码加密存储，接口请求携带身份校验信息，防止未授权访问；任务数据仅对所属公会成员可见。
- \*\*\*\*兼容性要求\*\*\*\*：前端页面兼容主流浏览器（Chrome、Edge、Firefox），支持
  PC 端访问；部署流程稳定可靠，每次代码提交可自动触发构建与部署。

## 三、系统设计 【中期必填】

### 1. 系统架构

> 本系统采用\*\*\*\*前后端分离架构\*\*\*\*，整体分为三层：

1.  \*\*\*\*前端层\*\*\*\*：基于 HTML/JavaScript 实现用户交互界面，通过
    esbuild 进行打包优化，最终部署于 GitHub Pages。
2.  \*\*\*\*后端服务层\*\*\*\*：基于 Spring Boot 开发 RESTful
    接口，提供用户管理、任务管理、数据统计等核心业务逻辑。
3.  \*\*\*\*数据持久层\*\*\*\*：通过 MyBatis（或其他 ORM 框架）操作
    MySQL 数据库，存储用户信息、公会信息、任务信息等数据。

## 四、系统实现 【中期部分填写；结项补全】

### 1. 关键技术

- \*\*\*\*后端核心技术\*\*\*\*：基于 Spring Boot 的分层架构设计，通过
  Service 层封装业务逻辑，Controller 层提供 RESTful
  接口，实现前后端解耦；使用 MyBatis 实现数据库操作，简化 SQL 编写。
- \*\*\*\*前端构建与部署\*\*\*\*：使用 esbuild 对前端 JS
  代码进行打包与压缩，提升页面加载速度；通过 GitHub Actions
  配置deploy.yml工作流，实现代码提交后自动构建前端静态资源并部署至
  GitHub Pages，无需手动操作。
- \*\*\*\*版本控制与协作\*\*\*\*：通过 Git
  进行代码版本管理，团队成员通过分支开发、Pull Request
  进行代码合并，保障代码质量与版本可控。
