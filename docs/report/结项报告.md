## 一、项目概述

### 1. 项目背景

校园内各类社团、学生组织（"公会"）在任务管理中普遍存在以下痛点：任务分配不透明、进度追踪困难、成员反馈不及时、缺乏统一的任务流转与状态管理平台。本项目针对校园场景下的轻量化任务协作需求，开发一套
"校园公会任务流系统"，旨在解决学生组织内部任务发布、分配、执行、反馈的全流程管理问题，提升社团协作效率，降低沟通成本。

### 2. 系统目标

- 实现任务的创建、分配、状态更新与进度追踪，支持任务生命周期全流程管理。

- 为社团管理员提供成员管理、任务统计、进度监控功能，提升组织管理效率。

- 为普通成员提供任务接收、提交、反馈的统一入口，简化任务执行流程。

- 实现前端静态页面自动化构建与部署，保障系统可访问性与版本迭代效率。

- 交付稳定、安全、可直接投入校园场景使用的完整系统。

## 二、需求分析

### 1. 功能需求

系统基于"悬赏任务市场"模式，核心功能分为以下模块：

**用户与权限管理模块**

- 支持用户注册、登录、退出登录，基于 JWT 令牌的身份认证。

- 区分管理员与普通用户角色，管理员可封禁/解封用户、管理全部任务。

- 用户个人信息展示，包含虚拟积分、经验值、冒险者等级（RPG 成长体系）。

**任务悬赏市场模块**

- 用户可发布悬赏任务，填写标题、描述、分类、悬赏积分、任务期限。

- 发布时从用户积分中冻结悬赏金额，积分不足禁止发布。

- 任务大厅展示所有待接取任务，支持关键词搜索、分类筛选。

- 用户可浏览并接取他人发布的任务（不能接取自己的任务），接取采用乐观锁防并发。

- 任务状态完整流转：待接取 → 进行中 → 已完成 / 已取消。

- 发布者可确认任务完成，完成后悬赏积分转给接取者，同时接取者获得经验值升级。

- 发布者可取消未完成的任务，退还冻结积分；接取者可主动放弃已接取的任务。

- 过期任务由定时任务自动取消并退还积分。

**积分与等级模块**

- 发布任务时扣除积分，完成任务时获得积分和经验值（经验值 = 赏金 × 10）。

- 每 100 经验值升 1 级，等级在个人页面展示。

**管理模块**

- 管理员可查看系统统计数据（用户总数、任务总数、各状态分布）。

- 管理员可查看全部用户（分页）、封禁/解封用户。

- 管理员可按状态筛选查看全部任务（分页），可删除任务（待接取状态退还积分）。

**前端交互模块**

- 提供登录注册页、任务大厅、任务详情、发布悬赏、个人中心、管理面板等完整页面。

- 页面采用校园风设计，PC 端与移动端双适配。

- 前端与后端接口通过 Fetch API 通信，JWT 令牌自动携带，数据实时刷新。

- 静态资源通过 esbuild 压缩打包，通过 GitHub Actions 自动部署至 GitHub Pages。

- 搜索结果 300ms 防抖，操作按钮加锁防重复提交，分页浏览大量数据。

**核心业务流程**：用户注册 → 登录获取 JWT → 发布悬赏任务（冻结积分）→
其他用户浏览并接取任务 → 接取者完成任务 → 发布者确认完成（积分结算给接取者）
→ 积分/经验/等级自动更新。

### 2. 非功能需求

- **性能要求**：系统支持至少 50
  名用户同时在线访问，页面响应时间≤2s；前端静态资源构建与部署流程耗时≤5
  分钟。

- **安全要求**：用户密码采用 BCrypt 加密存储，杜绝明文存储；核心接口通过
  JWT 令牌校验身份，未认证请求返回 401；任务数据按角色权限管控。

- **兼容性要求**：前端页面兼容主流浏览器（Chrome、Edge、Firefox），无页面错乱、按钮失效问题；后端服务运行稳定，无内存溢出、接口报错等异常问题。

- **运维要求**：项目代码提交自动触发 GitHub Actions 打包部署，无需人工手动部署，版本迭代便捷高效。

## 三、系统设计

### 1. 系统架构

本系统采用**前后端分离架构**，整体分为三层：

1.  **前端层**：基于 HTML/JavaScript/CSS 实现 SPA 单页应用，通过 esbuild
    进行打包优化，最终部署于 GitHub Pages。

 2.  **后端服务层**：基于 Spring Boot 开发 RESTful 接口，采用
     Controller/Service/Repository
     分层架构，提供用户认证、任务市场、积分结算、后台管理等核心业务逻辑。

 3.  **数据持久层**：通过 Spring Data JPA 操作数据库（开发环境 H2，生产环境
     MySQL），统一使用 JPA Repository 接口。

## 四、系统实现

### 1. 关键技术

- **后端核心技术**：基于 Spring Boot 的分层架构设计，通过 Service
  层封装业务逻辑，Controller 层提供 RESTful 接口，实现前后端解耦；使用
  Spring Data JPA 实现数据库操作，简化持久层编写；统一封装全局返回结果类。

- **密码加密与权限校验**：用户密码采用加密算法存储，杜绝明文存储漏洞；所有核心接口添加登录身份校验，拦截未授权访问，实现权限精准管控。

- **前端构建与部署**：使用 esbuild 对前端 JS
  代码进行打包与压缩，提升页面加载速度；通过 GitHub Actions 配置
  deploy.yml 工作流，实现代码提交后自动构建前端静态资源并部署至 GitHub
  Pages，无需手动操作。

- **任务状态全自动流转**：后端内置任务状态逻辑规则，任务状态随用户操作自动更新；过期任务由定时调度器
  自动取消并退还积分，业务流程高度自动化。

### 2. 界面展示（已完成页面）

1.  **用户登录/注册页面**：简洁校园风格表单，支持新用户注册、老用户账号密码登录，输入错误实时弹出文字提示。

2.  **任务大厅（Dashboard）**：浏览所有待接取的悬赏任务，支持关键词搜索（300ms 防抖）与分类筛选，任务卡片展示标题、赏金、发布者、浏览量和时间。

3.  **任务详情页**：查看任务完整描述、状态、发布者与接取者信息；根据用户身份和任务状态展示不同操作按钮（接取/确认完成/取消/放弃）。

4.  **发布悬赏页**：填写任务标题、选择分类、描述详情、设定悬赏积分（含快捷预设）和任务期限，提交时自动校验积分余额。

5.  **个人中心**：展示用户头像、昵称、积分、经验值等级进度条；切换查看"我发布的"和"我接取的"任务列表，支持分页浏览。

6.  **管理面板**：管理员专属，展示用户/任务统计数据看板；用户管理（分页列表、封禁/解封）；任务管理（按状态筛选、分页列表、删除任务）。

@Transactional
public void settleReward(User accepter, int reward) {
    accepter.setPoints(accepter.getPoints() + reward);
    int expGain = reward * 10;
    accepter.setExperience(accepter.getExperience() + expGain);
    int newLevel = (accepter.getExperience() / 100) + 1;
    if (newLevel > accepter.getGuildLevel()) {
        accepter.setGuildLevel(newLevel);
    }
    userRepository.save(accepter);
}

## 六、用户手册

### 1. 安装部署说明

#### （1）后端部署步骤

1.  环境准备：安装 JDK 17、Maven。

2.  数据库：开发环境使用内置 H2 数据库（零配置），生产环境配置 MySQL 8.0 并执行 sql/schema.sql 脚本。

3.  项目打包：进入 server 目录，执行 `.\mvnw.cmd clean package` 打包。

4.  启动服务：运行 `.\mvnw.cmd spring-boot:run`，默认端口 8080。

5.  Swagger UI（开发环境）：访问 http://localhost:8080/swagger-ui.html 查看 API 文档。

#### （2）前端部署步骤

1.  本地运行：直接打开 `ui/index.html` 文件即可访问前端页面。

2.  生产构建：执行 `npx esbuild js/app.js --bundle --outfile=js/bundle.js --minify`。

3.  GitHub Pages 部署：将前端代码推送到仓库 main 分支，GitHub Actions 自动构建部署。

### 2. 操作指南

#### （1）用户注册与登录

1.  访问系统首页，点击"注册"按钮，填写用户名、密码、昵称完成注册。

2.  注册成功后，返回登录页面，输入用户名和密码登录系统。

#### （2）浏览与接取任务

1.  登录后进入"任务大厅"，浏览待接取的悬赏任务。

2.  使用顶部搜索框输入关键词搜索，或点击分类按钮筛选任务。

3.  点击任务卡片查看详情，点击"接取任务"按钮接取。

#### （3）发布悬赏任务

1.  点击导航栏"发布悬赏"，填写任务标题、选择分类、描述详情。

2.  设定悬赏积分（可使用快捷预设 10/20/50）和任务期限（默认 7 天）。

3.  点击"发布任务"，系统自动冻结相应积分。

#### （4）管理我的任务

1.  进入"个人中心"，切换"我发布的"/"我接取的"查看任务列表。

2.  发布的待接取任务可取消（退还积分）；进行中的任务可确认完成。

3.  接取的进行中任务可主动放弃，回到待接取状态供他人接取。

#### （5）管理员功能

1.  使用管理员账号登录后，导航栏出现"管理"入口。

2.  查看系统统计看板（用户总数、任务总数、各状态分布）。

3.  用户管理：浏览全部用户，对违规用户执行封禁/解封。

4.  任务管理：按状态筛选全部任务，对异常任务执行删除。

## 七、项目总结

### 1. 阶段成果总结

- 已完成核心数据库表设计与 Spring Boot 后端框架搭建，实现了用户认证（JWT）、

  的全部接口开发与单元测试（23 个测试方法全部通过）。

  任务详情（操作按钮随状态切换）、发布悬赏（积分预设/期限输入）、个人中心
  （积分/经验/等级展示/分页）、管理面板（统计/用户管理/任务管理）等完整页面。

- 配置完成 GitHub Actions 自动化部署流程，前端代码推送后自动构建并部署至
  GitHub Pages。

- 完成了系统全面功能测试与 Bug 修复，修复了 NPE 401、重复取消刷积分、
  搜索混入状态、过期任务残留等关键问题。

### 2. 不足与后续改进方向

- 当前不足：

  1.  任务通知提醒功能尚未实现，用户无法实时接收任务状态变更通知。

  2.  缺少任务编辑和用户资料编辑功能，发布后的任务和注册信息不可修改。

  3.  单元测试仅覆盖 Service 层，Controller 和 Repository 层缺少集成测试。

- 后续计划：

  1.  增加站内通知功能，任务被接取/完成/取消时推送消息。

  2.  增加任务编辑和个人信息编辑接口与前端界面。

  3.  补充集成测试用例，提升代码覆盖率。
