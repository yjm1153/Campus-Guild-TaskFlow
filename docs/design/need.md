# 校园公会任务流系统 需求分析
## 一、项目背景
校园内各类社团、学生组织（"公会"）在任务管理中普遍存在以下痛点：任务分配不透明、进度追踪困难、成员反馈不及时、缺乏统一的任务流转与状态管理平台。本项目针对校园场景下的轻量化任务协作需求，开发一套"校园公会任务流系统"，旨在解决学生组织内部任务发布、分配、执行、反馈的全流程管理问题，提升社团协作效率，降低沟通成本。
## 二、功能需求
系统基于"悬赏任务市场"模式，核心功能分为以下模块：
### （一）用户与权限管理模块
- 支持用户注册、登录、退出登录，基于JWT令牌的身份认证。
- 区分管理员与普通用户角色，管理员可封禁/解封用户、管理全部任务。
- 用户个人信息展示，包含虚拟积分、经验值、冒险者等级（RPG成长体系）。
### （二）任务悬赏市场模块
- 用户可发布悬赏任务，填写标题、描述、分类、悬赏积分、任务期限。
- 发布时从用户积分中冻结悬赏金额，积分不足禁止发布。
- 任务大厅展示所有待接取任务，支持关键词搜索、分类筛选。
- 用户可浏览并接取他人发布的任务（不能接取自己的任务），接取采用乐观锁防并发。
- 任务状态完整流转：待接取 → 进行中 → 已完成 / 已取消。
- 发布者可确认任务完成，完成后悬赏积分转给接取者，同时接取者获得经验值升级。
- 发布者可取消未完成的任务，退还冻结积分；接取者可主动放弃已接取的任务。
- 过期任务由定时任务自动取消并退还积分。
### （三）积分与等级模块
- 发布任务时扣除积分，完成任务时获得积分和经验值（经验值 = 赏金 × 10）。
- 每100经验值升1级，等级在个人页面展示。
### （四）管理模块
- 管理员可查看系统统计数据（用户总数、任务总数、各状态分布）。
- 管理员可查看全部用户（分页）、封禁/解封用户。
- 管理员可按状态筛选查看全部任务（分页），可删除任务（待接取状态退还积分）。
### （五）前端交互模块
- 提供登录注册页、任务大厅、任务详情、发布悬赏、个人中心、管理面板等完整页面。
- 页面采用校园风设计，PC端与移动端双适配。
- 前端与后端接口通过Fetch API通信，JWT令牌自动携带，数据实时刷新。
- 静态资源通过esbuild压缩打包，通过GitHub Actions自动部署至GitHub Pages。
- 搜索结果300ms防抖，操作按钮加锁防重复提交，分页浏览大量数据。
### （六）核心业务流程
用户注册 → 登录获取JWT → 发布悬赏任务（冻结积分）→ 其他用户浏览并接取任务 → 接取者完成任务 → 发布者确认完成（积分结算给接取者）→ 积分/经验/等级自动更新。
## 三、非功能需求
- 性能要求：系统支持至少50名用户同时在线访问，页面响应时间≤2s；前端静态资源构建与部署流程耗时≤5分钟。
- 安全要求：用户密码加密存储，接口请求携带身份校验信息，防止未授权访问；任务数据仅对所属公会成员可见。
- 兼容性要求：前端页面兼容主流浏览器（Chrome、Edge、Firefox），无页面错乱、按钮失效问题；后端服务运行稳定，无内存溢出、接口报错等异常问题。
- 运维要求：项目代码提交自动触发自动化打包部署，无需人工手动部署，版本迭代便捷高效。
